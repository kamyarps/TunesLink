## Release setup

### App signing (do this before the first upload)

Under **Test and release → App integrity → Play app signing**, choose
**Use existing app signing key** and upload the same key that signs GitHub releases. Then a
GitHub APK and the Play version can update each other without an uninstall, and the pairing
survives the switch.

1. In Play Console, choose **Export and upload a key from Java keystore** and download
   `pepk.jar` and the encryption public key.
2. Run this with the release keystore (the one in the `ANDROID_KEYSTORE_BASE64` GitHub secret):

   ```bash
   java -jar pepk.jar --keystore=tuneslink-release.jks --alias=<key alias> --output=tuneslink-signing-key.zip --include-cert --rsa-aes-encryption --encryption-key-path=encryption_public_key.pem
   ```

3. Upload `tuneslink-signing-key.zip`. Signing your uploads with the same key is the simplest
   setup, because the release workflow already holds that key.

### Building the bundle

Only the Play bundle contains demo mode; `TunesLink.apk` never does.

- **Release workflow:** each tagged release uploads a private `TunesLink-play-bundle` workflow
  artifact containing `TunesLink.aab` and its `mapping.txt`. It is not attached to the GitHub
  release.
- **Locally:** with `android/keystore.properties` set up, run

  ```powershell
  .\scripts\build.ps1 -Component Android -PlayBundle
  ```

  This writes `artifacts/TunesLink.apk` (GitHub) and `artifacts/TunesLink.aab` (Play).

Upload `mapping.txt` under **App bundle explorer → Downloads → ReTrace mapping file** so crash
reports are readable.

The `versionCode` in `android/app/build.gradle` must increase with every Play upload.

### Closed test (required for new personal accounts)

Production access is unlocked after a closed test with **at least 12 testers who stay opted in
for 14 days in a row**.

1. **Test and release → Testing → Closed testing → Create track.** Upload `TunesLink.aab`.
2. Add testers with an email list or a Google Group. Invite 15–20 people so the count stays at 12
   or more even if a few drop out.
3. Send testers the opt-in link. Each one must accept it and install the app from Play.
4. Testers without a Windows PC and iTunes can use the demo (steps above). Testers with a PC can
   run TunesLink Bridge.
5. After 14 days, apply for production under **Dashboard → Apply for production**. Google asks
   how testers used the app and what changed because of their feedback, so keep notes.

## Removing demo mode later

It takes one commit:

1. Delete `android/app/src/demo`, `android/app/src/demoStub`, and `android/app/src/testDemo`.
2. Remove the `TunesLink.playDemo` lines from `android/app/build.gradle`.
3. Remove the `DemoBridge.ENABLED` checks: three in `BridgeClient.java`, one in
   `TuneLinkViewModel.kt`, and one assertion in `TuneLinkAccessibilityTest.kt`.
4. Remove `-PTunesLink.playDemo=true` from `scripts/build.ps1`, `ci.yml`, and `release.yml`.
5. Remove the "Demo mode" section from `PRIVACY.md`.

At the same time, change App access to instructions plus the video, because Google reviews every
update.
